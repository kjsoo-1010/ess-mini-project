# DAY 2 - 모델 개발 및 평가 기록

DAY 1 설계([MODEL_STRATEGY.md](MODEL_STRATEGY.md))를 구현하고 평가한 과정을 정리한 문서다. 무엇을 가정했고, 어떤 가설이 맞고 틀렸는지를 순서대로 적었다.

## 1. 결과 요약

선택된 모델은 **ΔQ(V) 분산 하나를 쓰는 선형 회귀**다. log10(수명)을 log10(ΔQ(V) 분산)의 직선으로 예측한다.

| 구분 | MAPE (%) | 비고 |
|---|---|---|
| Train (Batch 1 CV) | 9.28 | Train 셀 32개의 반복 5-fold 교차검증 평균 |
| Valid (Batch 1 Hold-out) | 8.87 | Train 셀로 학습, Hold-out 셀 9개로 평가 |
| Test (Batch 2) | 26.17 | Batch 1 전체(41개)로 학습 |
| Gap (Train-Valid) | -0.41 | (+) : 과적합 의심 |
| Gap (Valid-Test) | 17.30 | (+) : 배치간 일반화 저하 의심 |
| Gap (Target-Test) | 17.07 | Target : 원논문 9.1% |
| Test (Batch 3) | 13.25 | Batch 1 전체로 학습 |
| Gap (Batch2-Batch3) | -12.92 | Test 성능 간 비교 |
| Gap (Target-Test, Batch 3) | 4.15 | Batch 3 기준, 원논문 성능 비교 |

Gap 은 MAPE 가 낮을수록 좋은 지표이므로 "뒤 단계 − 앞 단계"로 계산했다. 양수면 뒤 단계에서 성능이 나빠진 것이다.

핵심 결론은 세 가지다.

- **Batch 1 안에서는 목표 수준이다.** CV 9.28%, Hold-out 8.87%로 원논문의 9.1%와 비슷하고 과적합 징후가 없다.
- **Batch 2 에서는 26.17%로 크게 나빠진다.** 원인은 셀별 예측 실패가 아니라 배치 전체의 일정한 편향이다. 예측 수명이 실제보다 일괄적으로 약 1.25배 길다.
- **순위는 완벽하게 맞는다.** 예측 수명으로 장·단수명을 가르는 AUC 가 Batch 2 와 3 모두 1.00이다. 모델은 "어느 셀이 더 오래 가는가"는 알지만 "새 배치의 수명 수준"은 모른다.

## 2. 코드 구조

```text
src/
├── config.py       경로, 배치별 파일과 품질 처리 규칙, 과제 기준 상수
├── preprocess.py   .mat 로딩과 정제 -> Dataset
├── features.py     초기 사이클 피처 정의와 피처 표
├── models.py       후보 모델 정의 (ModelSpec)
├── evaluation.py   분할, 교차검증, 지표, 모델 선택 규칙
├── report.py       리포팅 표와 그림
├── train.py        공식 실험 파이프라인 (실행 진입점)
├── analysis.py     사후 분석 (실행 진입점)
├── screening.py    단수명 셀 선별 실험 (실행 진입점)
├── zeroshot.py     Zero-shot 분류 실험 (실행 진입점)
└── replication.py  원논문 모델 구성의 재구현과 비교 (실행 진입점)
tests/test_pipeline.py   합성 데이터로 핵심 규칙을 검증
results/                 실행 결과 (CSV, 그림)
```

```bash
uv sync                      # 또는 pip install -r requirements.txt
python -m src.train          # 공식 성능 : results/model_performance.csv 등
python -m src.analysis       # 사후 분석 : results/posthoc_*.csv
python -m src.screening      # 단수명 셀 선별 : results/screening_*.csv
python -m src.zeroshot       # Zero-shot 분류 : results/zeroshot_*.csv
python -m src.replication    # 원논문 모델 비교 : results/paper_models.csv
python -m pytest             # 테스트
```

`src.train` 은 약 10초가 걸린다. 원본 파일에서 필요한 부분(summary 전체와 초기 100 사이클의 전압 곡선)만 읽기 때문이다.

설계에서 지킨 원칙은 다음과 같다.

| 원칙 | 구현 |
|---|---|
| 입력 범위 밖의 값이 피처에 섞이지 않게 한다 | 피처 함수는 `Dataset.early_window(100)` 으로 잘라낸 데이터만 받는다. 테스트가 "100 사이클 이후 값을 바꿔도 피처가 같다"는 것을 확인한다 |
| 전처리 기준은 학습 데이터에서만 구한다 | 스케일링과 로그 변환이 모델 파이프라인 안에 있어, 교차검증의 fold 마다 학습 부분으로만 맞춰진다 |
| 세 배치에 같은 규칙을 적용한다 | 정제 규칙은 `clean_summary` 하나이고, 배치별로 다른 것은 `config.py` 의 제외 셀과 수명 보정값뿐이다 |
| 사전에 정한 것과 사후에 떠올린 것을 섞지 않는다 | 후보 구성은 `train.py` 상단의 상수로 고정했고, 테스트 결과를 본 뒤의 실험은 `analysis.py` 로 분리했다 |
| 후보를 추가하기 쉽게 한다 | 피처는 `FEATURES` 에, 모델은 `ModelSpec` 으로 한 줄씩 등록한다. 평가 코드는 수정할 필요가 없다 |

## 3. 평가 절차

1. Batch 1 의 41개 셀을 셀 단위로 Train 32개와 Valid(Hold-out) 9개로 나눈다. 수명 구간(4분위)별 비율을 유지해 장수 셀이 한쪽에 몰리지 않게 했다.
2. Train 32개 안에서 5-fold 교차검증을 10회 반복해(총 50개 fold) 후보 모델을 비교한다.
3. 모델 선택은 CV 점수만으로 한다. 기준 모델을 유지하되, CV MAPE 가 표준오차보다 크게 앞서는 후보가 있을 때만 바꾼다. 셀이 32개뿐이라 작은 차이는 우연일 수 있기 때문이다.
4. Train 으로 학습한 모델을 Valid 에서 확인한다.
5. Batch 1 전체로 다시 학습한 모델을 Batch 2 와 Batch 3 에서 평가한다.

DAY 1 설계서에서는 교차검증 여부를 정하지 않았다. 가이드의 리포팅 포맷이 Train (Batch 1 CV) 를 요구하고, Hold-out 9개만으로는 수치가 분할에 따라 크게 흔들리기 때문에 교차검증을 함께 쓰기로 했다. 실제로 분할을 20번 바꿔 보면 CV 는 9.32 ± 0.69, Valid 는 9.28 ± 2.19다. Valid 수치 하나(8.87)는 4.8에서 13.0 사이에서 움직일 수 있는 값이다.

같은 충전 정책의 셀이 학습과 검증에 나뉘어 점수가 좋게 나오는지도 확인했다. 정책 단위로 묶은 CV 의 MAPE 는 9.45로 9.28과 차이가 없다.

**테스트 데이터 접근 기록.** Batch 2 와 3 의 라벨은 두 번 사용했다. 첫 번째는 사전에 정한 후보 전체의 평가이고(4절), 두 번째는 그 결과를 본 뒤의 사후 분석이다(6절). 1절의 공식 성능은 첫 번째 평가의 값이며, 사후 분석의 결과로 바꾸지 않았다.

## 4. 가설 검증 : 사전에 정한 후보

후보 구성은 DAY 1 전략에서 가져왔다. 모든 수치는 `results/model_comparison.csv` 에 있다.

| 모델 | 피처 수 | CV MAPE | Valid | Batch 2 | Batch 3 |
|---|---|---|---|---|---|
| mean (평균 예측) | - | 23.35 | 24.60 | 73.24 | 18.79 |
| **linear[core]** (ΔQ 분산) | 1 | 9.28 | 8.87 | 26.17 | 13.25 |
| linear[log_dq_var_smooth] | 1 | 9.25 | 8.49 | 28.28 | 13.17 |
| linear[core + 충전 시간] | 2 | 9.26 | 10.56 | 25.85 | 11.78 |
| linear[core + 평균 온도] | 2 | 9.62 | 8.43 | 26.48 | 12.48 |
| linear[core + 초기 용량 변화] | 2 | 11.03 | 8.29 | 23.68 | 14.81 |
| ridge[all] | 4 | 10.16 | 12.10 | 27.56 | 13.54 |
| elastic_net[all] | 4 | 10.54 | 12.37 | 23.48 | 11.77 |
| random_forest[all] | 4 | 10.20 | 10.44 | 32.72 | 12.15 |
| gradient_boosting[all] | 4 | 9.10 | 12.37 | 28.85 | 11.91 |

CV MAPE 의 표준오차는 0.4 ~ 0.6이다. Batch 2 와 3 열은 참고용이며 모델 선택에 쓰지 않았다.

| # | 가설 | 결과 | 판정 |
|---|---|---|---|
| H1 | ΔQ(V) 분산 하나로 수명을 예측할 수 있다 | 평균 예측 23.35 -> 9.28 | 채택 |
| H2 | 인접 사이클의 중앙값 곡선을 쓰면 측정 노이즈에 덜 흔들려 성능이 오른다 | 9.25 vs 9.28. 차이가 표준오차(0.43)보다 작다 | 기각 |
| H3 | 보조 피처(충전 시간, 평균 온도, 초기 용량 변화)를 더하면 성능이 오른다 | 9.26, 9.62, 11.03. 어느 것도 나아지지 않는다 | 기각 |
| H4 | 여러 피처를 쓰는 규제 선형 모델이나 트리 모델이 더 낫다 | 가장 좋은 gradient boosting 이 9.10으로 표준오차 이내. 나머지는 더 나쁘다 | 기각 |
| H5 | Batch 1 에서 학습한 관계가 Batch 2 에 그대로 적용된다 | Batch 2 에서 26.17% | 수준은 기각, 순위는 채택 (5절) |
| H6 | 트리 계열은 학습 범위 밖을 예측하지 못해 Batch 2 에서 불리하다 | random forest 32.72, gradient boosting 28.85, 선형 26.17 | 채택. 다만 주된 오차 원인은 아니다 |

H2 ~ H4 가 모두 기각되어 기준 모델인 `linear[core]` 가 그대로 선택됐다. 셀이 32개인 학습 데이터에서는 피처나 모델을 늘려서 얻는 이득이 변동 폭 안에 묻힌다.

DAY 1 전략과 달라진 점이 하나 있다. 보조 후보였던 **내부저항 변화는 후보에서 빠졌다.** Batch 2 의 6개 셀은 초기 100 사이클에 내부저항 측정값이 없어서 피처를 계산할 수 없다. 테스트에서 쓸 수 없는 피처는 학습에도 쓰지 않는다. 이 처리는 `available_features` 가 자동으로 한다.

## 5. 우회 분류 : 예측 수명으로 장·단수명 판정

DAY 1 에서 계획한 대로, 예측 수명이 550 사이클 이상이면 장수명으로 판정했다. 입력이 초기 100 사이클이므로 원논문의 분류 실험(초기 5 사이클, 정확도 95.1%)과는 조건이 다르다.

| 평가 대상 | 장수명 / 단수명 | Accuracy | F1 (장수명) | F1 (단수명) | AUC |
|---|---|---|---|---|---|
| Batch 2 | 9 / 30 | 0.538 | 0.500 | 0.571 | 1.000 |
| Batch 3 | 39 / 1 | 0.975 | 0.987 | 0.000 | 1.000 |
| Batch 2 + 3 | 48 / 31 | 0.759 | 0.835 | 0.558 | 0.997 |

- **AUC 가 1.00이다.** 예측 수명 순으로 줄을 세우면 실제 단수명 셀이 빠짐없이 앞에 온다. 단수명 예시가 1개뿐인 Batch 1 로 학습했는데도 선별 순서는 정확하다.
- **Accuracy 는 Batch 2 에서 0.538이다.** (9절에서 판정 규칙을 바꿔 0.949까지 올렸다.) 예측이 일괄적으로 길게 나와서, 실제 수명이 393 ~ 514인 단수명 셀 18개가 580 ~ 730으로 예측되어 장수명으로 판정됐다. 반대 방향의 오분류는 없다. 순서는 맞고 기준선의 위치가 어긋난 것이다.
- Batch 3 의 0.975는 39개가 장수명이어서 나오는 값이다. 단수명 셀 1개(541)는 593으로 예측해 맞히지 못했다.

## 6. 오류 분석과 사후 가설

Batch 2 의 오차 원인을 진단하고, 그 결과로 세운 가설을 검증했다. 이 절의 수치는 테스트 라벨을 보고 얻은 것이라 공식 성능이 아니다. `python -m src.analysis` 로 재현된다.

### 6.1 오차가 큰 셀

| 구분 | 셀 | 실제 | 예측 | 오차 |
|---|---|---|---|---|
| Batch 2 | b2c18 `5.2C(50%)-4.25C` | 449 | 730 | 62.7% |
| Batch 2 | b2c6 `3.6C(9%)-5C` | 393 | 632 | 60.9% |
| Batch 2 | b2c15 `3.6C(9%)-5C` | 396 | 625 | 57.9% |
| Batch 2 | b2c9 `5.6C(26%)-4.5C` (ns) | 791 | 1227 | 55.2% |
| Batch 3 | b3c40 `5.6C(19%)-4.6C` (ns) | 796 | 1179 | 48.1% |
| Batch 3 | b3c38 `5C(67%)-4C` (ns) | 1935 | 1225 | 36.7% |
| Valid | b1c2 `3.6C(80%)-3.6C` | 2237 | 1629 | 27.2% |

공통점은 두 가지다.

- **Batch 2 는 39개 중 38개를 길게 예측했다.** 일반 셀과 `newstructure` 셀 모두 같은 방향이다.
- **수명이 1,800 이상인 셀은 짧게 예측했다.** Batch 1 의 Hold-out(2237 -> 1629)과 Batch 3(1935 -> 1225, 1836 -> 1380, 1801 -> 1417)에서 같은 현상이 나온다. 수명이 매우 긴 셀은 초기 100 사이클의 ΔQ(V) 가 0에 가까워 분산이 측정 노이즈 수준이 되고, 그보다 더 긴 수명을 구분하지 못한다.

### 6.2 사후 가설

| # | 가설 | 결과 | 판정 |
|---|---|---|---|
| P1 | Batch 2 의 오차는 배치 전체의 일정한 편향이다 | 예측 / 실제가 Batch 2 일반 셀 1.26배, `newstructure` 셀 1.23배, Batch 3 1.05배. 편향을 제거하면 MAPE 가 9.5%, 14.1%, 11.5% | 채택 |
| P2 | ΔQ(V) 의 기준 사이클(cycle 10)을 바꾸면 편향이 줄어든다 | cycle 3 ~ 40 어느 것을 써도 Batch 2 편향이 1.21 ~ 1.25배로 남는다 | 기각 |
| P3 | 초기 용량 상승폭을 피처로 더하면 배치 차이가 설명된다 | Batch 1 CV 7.85, Batch 2 21.6으로 좋아지지만 Batch 3 가 13.3 -> 21.9로 나빠진다 | 기각 |
| P4 | 초기 용량의 절대 수준을 피처로 더하면 성능이 오른다 | Batch 1 CV 는 6.87로 가장 좋지만 Batch 2 가 44.8로 크게 나빠진다 | 기각 |
| P5 | 새 배치에서 수명이 확인된 셀 몇 개로 기준선만 보정하면 해결된다 | Batch 2 : 1개로 15.0%, 3개로 12.5%, 5개로 11.8%. 분류 정확도는 5개로 0.951 | 채택 |

P1 과 P2 를 합치면, 오차는 피처 정의의 문제가 아니라 **배치 수준의 차이**다. Batch 2 는 같은 ΔQ(V) 분산에서 수명이 약 20% 짧다. `results/figures/core_feature_fit.png` 에서 Batch 2 의 점들이 Batch 1 의 회귀선 아래에 평행하게 놓인 것으로 확인된다.

P4 는 DAY 1 의 판단을 뒷받침한다. EDA 에서 "용량의 절대 수준은 배치마다 달라 배치 차이가 그대로 들어간다"는 이유로 이 피처를 제외했다. CV 점수만 보고 골랐다면 이 피처가 선택됐을 것이고(9.28 -> 6.87), Batch 2 오차는 26%에서 45%로 커졌을 것이다. P3 도 같은 종류다. Batch 1 안에서의 개선이 다른 배치로 이어진다는 보장이 없다.

학습 배치가 하나뿐이면 배치 간 차이를 데이터에서 배울 수 없다. 원논문은 두 배치를 섞어 학습했고, 이 과제는 Batch 1 만으로 학습한다. 편향을 라벨 없이 없애는 방법은 찾지 못했다.

### 6.3 기준선 보정 (P5)

Batch 2 에서 무작위로 고른 k 개 셀의 실제 수명으로 예측의 절편만 보정하고, 나머지 셀로 평가했다 (500회 반복 평균).

| 보정에 쓴 셀 수 | Batch 2 MAPE | Batch 2 분류 정확도 | Batch 3 MAPE |
|---|---|---|---|
| 0 (공식 결과) | 26.17 | 0.538 | 13.25 |
| 1 | 15.02 | 0.873 | 17.91 |
| 3 | 12.46 | 0.936 | 14.25 |
| 5 | 11.76 | 0.951 | 13.16 |
| 10 | 11.37 | 0.959 | 12.28 |

Batch 2 는 셀 3 ~ 5개면 오차가 절반 이하로 줄고, 분류 정확도가 0.95 수준이 된다. Batch 3 는 편향이 작아 보정의 효과가 거의 없고, 셀 1개로 보정하면 오히려 나빠진다.

이 수치는 테스트 라벨을 사용하므로 테스트 성능이 아니다. "현장에서 새 조건의 셀 몇 개가 수명을 다한 뒤 기준선을 다시 맞추면 어느 정도가 되는가"에 대한 추정이다.

## 8. ESS 운영 관점의 해석

**활용할 수 있는 것.**

- **셀 선별.** 초기 100 사이클만 돌려 보면 어느 셀이 먼저 수명을 다할지 순서를 알 수 있다(AUC 1.00). 팩을 구성할 때 수명이 비슷한 셀끼리 묶거나, 하위 셀을 걸러내는 데 쓸 수 있다.
- **교체 계획.** 같은 조건에서 수집한 데이터로 학습했다면 수명을 약 9% 오차로 예측한다. 수명 800 사이클인 셀이라면 ±70 사이클 정도다.

**한계.**

- **조건이 바뀌면 수명 수준이 어긋난다.** 시험 조건이 다른 배치에서는 예측이 일괄적으로 20% 이상 벗어났다. 실제 ESS 는 온도, 충·방전 패턴, 셀 제조 로트가 실험실보다 훨씬 다양하다.
- **수명이 매우 긴 셀은 짧게 예측한다.** 초기 100 사이클의 변화가 측정 노이즈 수준이면 구분할 수 없다.
- **초기 100 사이클이 필요하다.** DAY 1 에서 확인했듯이 5 사이클로는 신호가 없고 50 사이클부터 생긴다. 제조 직후 바로 선별하는 용도로는 쓸 수 없다.
- **셀 단위 결과다.** 모듈이나 랙 단위의 수명은 셀 간 불균형과 열 관리의 영향을 받으므로 이 결과를 그대로 적용할 수 없다.

**실제 적용에 필요한 것.** 새 조건(제조 로트, 운전 조건)마다 수명이 확인된 셀 몇 개로 기준선을 보정하는 절차가 있어야 한다. 이 데이터에서는 3 ~ 5개면 충분했다. 여러 조건의 데이터를 함께 학습해 조건 간 차이 자체를 모델이 배우게 하는 것이 근본적인 방법이다.

## 9. 추가 실험 : 단수명 셀 선별 (zero-shot, 이상 탐지)

5절의 우회 분류는 순서는 맞히지만(AUC 1.00) 판정 기준선이 어긋나 Batch 2 정확도가 0.538이었다. "학습에 없던 클래스를 가려내는" 문제로 보고 관련 문헌의 기법을 적용했다. 테스트 결과를 본 뒤의 실험이므로 공식 성능이 아니다. `python -m src.screening` 으로 재현된다.

### 9.1 문헌에서 가져온 아이디어

| 분야 | 아이디어 | 이 문제에 적용 |
|---|---|---|
| Zero-shot 학습 (Xian et al., 2019) | 본 적 없는 클래스를 중간 속성을 거쳐 인식한다 | "단수명"은 수명이라는 연속 속성의 구간이다. 수명을 예측한 뒤 구간으로 나누는 5절의 방식이 속성 기반 zero-shot 에 해당한다. 부족한 것은 판정 기준선의 보정이다 |
| Conformal prediction (Angelopoulos & Bates, 2021; Barber et al., 2021) | 학습 데이터의 교차검증 잔차로 예측의 하한을 분포 가정 없이 만든다 | 예측 수명의 하한이 550 이상일 때만 장수명으로 판정한다 |
| 이상 탐지 / one-class 분류 (Ruff et al., 2021) | 정상 데이터의 분포만 학습하고 벗어나면 이상으로 본다 | Batch 1 의 장수명 셀을 정상으로 학습한다 |
| Transductive 군집화 | 평가할 배치 전체의 피처를 라벨 없이 함께 본다 | 예측 수명이 두 덩어리로 갈리면 덩어리 단위로 판정한다 |

Positive-Unlabeled 학습과 비지도 도메인 적응도 검토했으나 적용하지 않았다. 전자는 분류기가 수명이 아니라 배치를 구분하게 되고, 후자는 같은 피처 값에서 수명이 달라지는 변화를 타깃 라벨 없이 교정하지 못한다.

### 9.2 방법

- **하한 판정.** Batch 1 의 leave-one-out 예측에서 log10(예측 / 실제)를 구하고, 그 90% 분위수를 여유로 삼는다. 예측 수명을 여유만큼 낮춘 값이 550 미만이면 단수명으로 판정한다. 여유는 Batch 1 만으로 정하며, 41개 셀 기준으로 1.19배다. 수준 90%는 conformal prediction 에서 흔히 쓰는 값으로 고정했다.
- **One-class 탐지기.** Mahalanobis 거리, Isolation Forest, One-Class SVM, Local Outlier Factor 를 세 가지 입력(ΔQ 분산 1개, 요약 피처 5개, ΔQ(V) 곡선의 주성분 5개)에 적용했다. 정상 셀의 95%를 받아들이는 점수를 기준으로 판정한다.
- **군집 + 하한.** 평가 배치의 예측 수명을 군집 1개 또는 2개로 나누고(BIC 로 선택), 군집 평균의 하한으로 군집 전체를 판정한다. 평가 대상의 피처를 쓰는 설정이다.

| 군집 + 하한 (90%) | - | 1.000 | 1.000 | 0.975 |

하한 판정의 세부 지표는 다음과 같다.

| 평가 대상 | 장수명 / 단수명 | Accuracy | F1 (장수명) | F1 (단수명) | 단수명 검출률 | 오경보율 |

- **하한 판정은 Batch 2 의 단수명 셀 30개 중 28개를 잡는다.** 놓친 2개는 실제 수명 449와 514인 셀이며, 예측이 730과 692로 특히 높았던 셀이다. 장수명 셀을 단수명으로 잘못 판정한 경우는 없다.
- **Batch 3 의 단수명 셀 1개(541)도 잡았다.** 대신 수명 667인 셀 하나를 단수명으로 판정했다.
- **대가는 Batch 1 내부의 오경보다.** 기준선만 쓸 때는 0%였던 오경보가 11 ~ 13%로 늘었다. 수명이 550을 조금 넘는 셀(예: 599)이 단수명으로 판정된다.
- **One-class 탐지기는 실패했다.** ΔQ 분산 하나만 쓰면 단수명 셀이 Batch 1 의 범위 안에 있어 거의 검출되지 않는다(검출률 0 ~ 0.37). 피처를 늘리면 검출률은 오르지만 장수명 셀까지 이상으로 판정한다. 8개 조합 중 7개에서 Batch 2 의 오경보율이 0.56 ~ 0.89이고(나머지 하나는 오경보가 없는 대신 검출률이 0.17), 장수명이 대부분인 Batch 3 에서 정확도가 0.05까지 떨어진다. 탐지기가 잡아내는 것은 "수명이 짧다"가 아니라 "Batch 1 과 다른 배치다"이다.
- **군집 + 하한은 Batch 2 를 전부 맞혔다.** Batch 2 의 예측 수명이 두 덩어리로 뚜렷이 갈리기 때문이다. Batch 3 와 Valid 는 군집 1개로 판정되어 전부 장수명이 됐고, Batch 3 의 단수명 셀 1개는 놓쳤다.

### 9.5 해석과 한계

- **하한 판정은 편향을 고친 것이 아니다.** Batch 2 의 편향(1.26배)은 여유(1.19배)보다 크다. 단수명 셀 대부분이 기준선에서 충분히 떨어져 있어 여유만으로 넘어온 것이다. 편향이 더 큰 배치에서는 같은 효과를 기대할 수 없다.
- **수준 90%는 결과를 본 뒤에 확정했다.** 계획 단계에서 80%, 90%, 95%의 Batch 2 결과를 이미 봤다. 관례적인 값으로 고정하고 다른 수준의 결과를 모두 공개했지만, 사전에 정한 실험과 같은 무게로 읽으면 안 된다. 80%였다면 Batch 2 정확도는 0.641이다.
- **conformal prediction 의 보장은 학습과 평가 데이터가 같은 분포일 때 성립한다.** 배치가 다르면 90%라는 수준이 그대로 지켜지지 않는다. 여기서는 보수적인 판정 규칙을 만드는 근거로만 썼다.
- **군집 방식은 평가할 셀들을 한꺼번에 볼 수 있을 때만 쓸 수 있고**, 배치 안에 수명이 다른 두 집단이 있을 때만 효과가 있다.
- **현장 관점.** 단수명 셀을 놓치는 비용이 장수명 셀을 한 번 더 검사하는 비용보다 크다면, 오경보 11 ~ 13%를 감수하고 하한 판정을 쓰는 것이 합리적이다. 수준은 두 비용의 비율로 정하면 된다.

### 9.6 입력을 초기 5 사이클로 줄였을 때

가이드의 Classification 조건인 초기 5 사이클로 같은 실험을 했다. 피처는 5 사이클 안에서 계산한 ΔQ(V) 분산 하나이고, 원논문의 정의(cycle 5 − cycle 4)와 가장 넓은 간격(cycle 5 − cycle 2) 두 가지를 썼다. 창마다 선형 회귀를 다시 맞췄다. 수치는 `results/screening_input_window.csv` 에 있다.

| 입력 | 회귀 MAPE (Batch 1 LOO / Batch 2 / Batch 3) | Batch 2 AUC | Batch 2 Accuracy (기준선만 / 하한 판정) | Batch 2 단수명 검출률 (하한 판정) |
|---|---|---|---|---|
| 100 사이클 (Q100 − Q10) | 9.4 / 26.2 / 13.3 | 1.000 | 0.538 / 0.949 | 0.933 |
| 5 사이클 (Q5 − Q4) | 24.1 / 72.4 / 18.7 | 0.456 | 0.231 / 0.231 | 0.000 |
| 5 사이클 (Q5 − Q2) | 24.5 / 78.8 / 19.5 | 0.241 | 0.231 / 0.282 | 0.100 |

- **5 사이클로는 선별이 되지 않는다.** Batch 2 의 AUC 가 0.5 이하로, 예측 수명의 순서가 실제 수명과 무관하거나 오히려 반대다. 정확도 0.231은 39개 셀을 전부 장수명으로 판정했을 때의 값이다.
- **회귀 자체가 평균 예측 수준이다.** Batch 1 LOO 의 MAPE 24%는 평균만 예측하는 기준 모델(23.4%)과 같다. 5 사이클의 ΔQ(V) 분산은 수명에 대한 정보를 담고 있지 않다.
- **하한 판정도 소용이 없다.** 예측이 부정확하면 여유가 1.4 ~ 1.5배로 넓어지는데, 순서가 맞지 않으니 여유를 넓혀도 단수명 셀을 골라내지 못한다. 하한 판정은 순서가 맞는 예측의 기준선을 옮기는 방법이지, 없는 신호를 만들어 내는 방법이 아니다.

이 결과는 DAY 1 에서 확인한 것(5 사이클의 ΔQ 분산과 수명의 상관 0.10, 50 사이클부터 신호가 생김)과 일치한다. 원논문은 5 사이클로 95.1%를 보고했지만, 학습 데이터에 단수명 셀이 충분히 있는 조건이었다.

### 9.7 Zero-shot 분류 모델 (생성형)

9.2 ~ 9.6 의 방법은 회귀 모델의 예측에 판정 규칙을 붙인 것이다. 여기서는 **별도의 이진 분류기**를 학습한다. 단수명 셀이 없어도 학습할 수 있도록, 단수명 클래스의 피처를 합성하는 생성형 zero-shot 방식(Xian et al., 2018)을 작은 데이터에 맞게 단순화했다. `python -m src.zeroshot` 으로 재현된다.

**방법.**

1. Batch 1 의 장수명 셀로 조건부 분포 p(피처 | 수명)을 학습한다. 피처를 log10(수명)의 선형 함수에 정규 잡음을 더한 것으로 본다.
2. 본 적 없는 클래스의 정의("수명이 150 이상 550 미만")에서 수명을 뽑아 그 클래스의 피처 2,000개를 합성한다. 하한 150은 가이드가 제시한 수명 범위의 하한이다.
3. 실제 장수명 셀과 합성한 단수명 셀로 로지스틱 회귀를 학습한다. 실제 단수명 셀(Batch 1 의 1개)은 학습에 쓰지 않는다.

**피처와 판정 기준의 선택.** 테스트 라벨 없이 고르기 위해 zero-shot 의 표준 검증 방식을 썼다. Batch 1 의 Train 셀에서 수명이 짧은 쪽 일부(하위 25%, 35%, 45%)를 학습에서 숨겨 "가짜 미관측 클래스"로 삼고, 나머지로 학습한 모델이 숨긴 셀을 얼마나 가려내는지(검출률)와 본 셀을 얼마나 장수명으로 유지하는지(정확도)의 조화평균 H 로 평가한다. 후보는 핵심 피처(ΔQ 분산)에 원논문의 후보 피처를 하나씩 더한 13개 묶음이고, 용량의 절대 수준과 내부저항은 뺐다.

| 피처 묶음 | 판정 기준 | 미관측 검출률 | 본 클래스 정확도 | H |
|---|---|---|---|---|
| ΔQ 분산 + 초기 용량 상승폭 (`qd_rise`) | 0.1 | 0.928 | 0.832 | 0.877 |
| ΔQ 분산 + ΔQ(2.0 V) | 0.1 | 0.939 | 0.792 | 0.853 |
| ΔQ 분산 + 충전 시간 | 0.1 | 0.914 | 0.776 | 0.836 |
| ΔQ 분산만 | 0.2 | 0.811 | 0.858 | 0.829 |

(상위 3개와 핵심 피처만. 전체는 `results/zeroshot_validation.csv`)

**결과 (Accuracy).**

| 구성 | Batch 1 (LOO) | Valid | Batch 2 | Batch 3 |
|---|---|---|---|---|
| ΔQ 분산만, 판정 기준 0.5 (검증 없음) | 0.969 | 1.000 | 0.538 | 0.975 |
| ΔQ 분산만, 판정 기준 0.2 (검증으로 정함) | 0.906 | 0.889 | 0.872 | 1.000 |
| **선택된 구성 : ΔQ 분산 + `qd_rise`, 판정 기준 0.1** | 0.875 | 0.889 | **0.974** | 0.975 |
| (비교) 9.3 의 하한 판정 90% | 0.875 | 0.889 | 0.949 | 0.975 |

선택된 구성의 세부 지표는 Batch 2 에서 F1(장수명) 0.947, F1(단수명) 0.983, 단수명 검출률 0.967(30개 중 29개), 오경보 0이다. Batch 3 에서는 오경보가 없지만 단수명 셀 1개(541)를 놓쳤다. Batch 1 내부의 오경보율은 0.129(LOO), 0.111(Valid)이다.

- **판정 기준을 검증으로 정한 것만으로 Batch 2 정확도가 0.538에서 0.872로 오른다.** 피처는 그대로 ΔQ 분산 하나다. 가짜 미관측 클래스 검증이 "본 적 없는 짧은 수명 쪽으로는 판정을 보수적으로 해야 한다"는 것을 Batch 1 안에서 찾아낸 것이다.
- **피처를 하나 더하면 0.974까지 오른다.** 다만 아래의 불안정성을 함께 봐야 한다.
- **9.3 의 하한 판정과 달리 수준을 테스트 결과를 본 뒤에 정하지 않았다.** 피처 묶음과 판정 기준 모두 Batch 1 의 Train 셀만으로 코드가 정한다.

**선택의 안정성.** Train / Valid 분할과 난수를 10번 바꿔 같은 절차를 반복했다 (`results/zeroshot_stability.csv`).

| 선택된 피처 묶음 | 횟수 | Batch 2 Accuracy |
|---|---|---|
| ΔQ 분산 + `qd_rise` | 6 | 0.974 |
| ΔQ 분산 + ΔQ(2.0 V) | 2 | 0.769 |
| ΔQ 분산만 | 1 | 0.821 |
| ΔQ 분산 + ΔQ 평균 | 1 | 0.641 |

10회의 Batch 2 정확도는 평균 0.884, 최소 0.641, 최대 0.974다. Batch 3 는 0.975 ~ 1.000이다. 어느 경우에도 판정 규칙이 없는 0.538보다는 높다.

**한계.**

- **선택이 불안정하다.** 검증 점수 H 의 차이가 작고(0.877 vs 0.853) Train 셀이 32개뿐이라, 분할에 따라 다른 피처가 선택된다. 기본 분할의 0.974는 10번 중 6번 나오는 결과다.
- **`qd_rise` 는 사후 진단에서도 나온 피처다.** 원논문의 후보 피처(최대 용량 − cycle 2 용량)이기는 하지만, 6.2절에서 Batch 2 의 오차를 진단하다가 떠올린 피처이기도 하다. 후보 목록에 넣은 판단이 테스트 결과와 완전히 무관하다고 할 수 없다. 이 피처는 회귀에서는 Batch 3 의 MAPE 를 13.3%에서 21.9%로 악화시켰다.
- **판정 기준 0.1은 후보 범위(0.1 ~ 0.9)의 끝값이다.** 더 낮은 값이 최적일 수 있으나 결과를 본 뒤에 범위를 넓히지 않았다.
- **단수명 클래스의 수명 범위(150 ~ 550)는 가정이다.** 합성하는 셀의 분포가 이 가정에 따라 달라진다.
- **입력은 여전히 초기 100 사이클이다.** 5 사이클로는 9.6 에서 본 것처럼 신호가 없다.

## 10. 원논문 모델 구성과의 비교

원논문의 수치(9.1% 등)는 학습·평가 데이터가 달라 이 프로젝트의 수치와 직접 비교할 수 없다. 그래서 반대로 접근했다. **원논문의 방법을 이 데이터셋에 그대로 적용해, 같은 데이터에서 비교한다.** `python -m src.replication` 으로 재현된다.

### 10.1 구현한 것

원논문은 후보 피처 20개(Supplementary Table 1)에서 세 가지 모델을 만든다. 피처 정의를 그대로 구현하고, 원논문과 같이 elastic net 으로 피처를 고르게 했다. 학습은 Batch 1 이고 평가 절차는 3절과 같다.

| 모델 | 후보 피처 | 구성 |
|---|---|---|
| Variance | 1개 | ΔQ(V) 분산. 이 프로젝트의 공식 모델과 같다 |
| Discharge | 13개 | ΔQ(V) 통계값 6개 + 용량 추세 7개 (기울기, 절편, cycle 2 용량, 최대 용량 − cycle 2 용량, cycle 100 용량) |
| Full | 20개 | 위 13개 + 충전 시간, 최고·최저 온도, 온도의 시간 적분, 내부저항 3개 |

원논문과 같지 않은 부분은 다음과 같다.

- **학습 데이터.** 원논문은 두 배치(2017-05-12, 2017-06-30)에서 41개 셀을 뽑아 학습했다. 여기서는 Batch 1(2017-05-12)의 41개 셀로 학습한다.
- **세부 설정.** 원논문의 모델링 코드는 공개되어 있지 않다. 규제 강도는 5-fold 교차검증으로 정했다.
- **내부저항.** Batch 2 의 6개 셀은 초기 100 사이클에 측정값이 없어 Full 모델로 평가할 수 없다. 내부저항 3개를 뺀 구성(17개)을 함께 돌렸다.

### 10.2 결과 (MAPE, %)

| 모델 | 선택된 피처 | Batch 1 CV | Valid | Batch 2 | Batch 3 | 원논문 2차 테스트 (= Batch 3) |
|---|---|---|---|---|---|---|
| Variance (공식 모델) | 1 / 1 | 9.28 | 8.87 | 26.17 | 13.25 | 11.4 |
| Discharge | 8 / 13 | 7.59 | 7.09 | 32.79 | 9.14 | 8.6 |
| Full | 11 / 20 | 9.80 | 9.77 | 34.25 (33개 셀) | 9.11 | 10.7 |
| Full, 내부저항 제외 | 10 / 17 | 10.01 | 9.58 | 35.31 | 9.10 | - |

- **Batch 3 에서는 원논문의 수치가 거의 재현된다.** Discharge 는 9.14% 대 8.6%, Full 은 9.11% 대 10.7%다. 원논문이 이 배치(2차 테스트)에서 보고한 값과 1 ~ 2%p 이내다. 학습 데이터가 다른데도 비슷한 수준이 나온다는 것은 구현과 데이터 처리가 원논문과 크게 어긋나지 않는다는 뜻이다.
- **피처를 늘리면 Batch 3 는 좋아지고 Batch 2 는 나빠진다.** Batch 3 는 13.25%에서 9.1%로 내려가지만, Batch 2 는 26.17%에서 32.8 ~ 35.3%로 올라간다.
- **Batch 2 에서는 가장 단순한 Variance 모델이 가장 낫다.** 필수 평가 대상인 Batch 2 기준으로는 공식 모델이 원논문의 다피처 모델보다 6 ~ 9%p 낮다.
- **세 배치에서 모두 좋은 모델은 없다.**

### 10.3 해석

elastic net 이 고른 피처에 **용량의 절대 수준**(cycle 100 용량, 마지막 10 사이클 추세의 절편)이 들어 있다. DAY 1 에서 "배치마다 수준이 달라 배치 차이가 그대로 들어간다"는 이유로 제외한 종류의 피처다. Batch 1 안에서는 이 피처가 수명을 더 잘 설명하지만(CV 9.28 -> 7.59), 용량 수준이 다른 배치에서는 그 관계가 배치에 따라 유리하게도 불리하게도 작용한다. 초기 용량은 Batch 3 가 가장 낮고(1.064 Ah) Batch 2 가 가장 높다(1.094 Ah).

교차검증 점수만으로 모델을 골랐다면 Discharge 가 선택된다(7.59 는 9.28 보다 표준오차 이상 낮다). 그 경우 Batch 3 는 9.14%로 좋아지지만 필수 평가인 Batch 2 는 32.79%가 된다. 이 구성은 DAY 1 전략의 후보에 없었으므로 공식 결과는 바꾸지 않았다.

원논문과의 차이를 정리하면 이렇다.

| 비교 | 결과 |
|---|---|
| 원논문 수치와의 직접 비교 | Batch 3 에서만 가능. 같은 모델 구성끼리 1 ~ 2%p 차이 |
| 같은 데이터에서 원논문 방법과 비교 (Batch 2) | 공식 모델 26.17% < Discharge 32.79% < Full 34.25% |
| 같은 데이터에서 원논문 방법과 비교 (Batch 3) | Discharge 9.14%, Full 9.11% < 공식 모델 13.25% |

Batch 2 의 오차가 큰 것은 이 프로젝트의 모델이 원논문보다 못해서가 아니다. 원논문의 방법을 그대로 써도 Batch 2 에서는 더 나빠진다. Batch 2 는 원논문에 없는 배치이고, Batch 1 만으로는 배울 수 없는 배치 수준의 차이가 있다.
